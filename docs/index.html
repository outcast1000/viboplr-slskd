Set up slskd

Viboplr can't speak Soulseek itself, so the Soulseek plugin drives slskd: a free, open-source Soulseek daemon that you install and run. It's a ten-minute job. slskd stays yours — its files, its settings, its process; Viboplr only talks to it over its local API.

Your API key. Generated by the Soulseek plugin and already filled into the config below; it must match the API key field in the plugin.
generating…

You opened this page directly, so the key above was made here. Paste it into the plugin's API key field in Viboplr as well — or open this page from the plugin (Soulseek in the sidebar → Open setup guide) and it arrives with the plugin's own key filled in.

  1. Download

    Get slskd-<version>-win-x64.zip from the releases page and extract it somewhere it can stay, for example C:\slskd. It's a single slskd.exe plus a few files.

    Open slskd releases

  2. Run it once

    Double-click slskd.exe. A console window opens and slskd creates its settings folder at %LOCALAPPDATA%\slskd with a slskd.yml inside. Close the window (or press Ctrl+C) before the next step.

    The first start asks to allow incoming connections (port 50300). Allow it — otherwise other Soulseek users can't reach you and downloads are slow to start.

  3. Configure

    Paste %LOCALAPPDATA%\slskd\slskd.yml into the Explorer address bar, or open it from Notepad. Add the lines below (indentation matters — two spaces per level). Replace the two Soulseek placeholders with your own account; the key is already yours. If the file already has an uncommented soulseek:, shares: or web: section, add the lines inside it instead of repeating the heading.

    Shared folders. Soulseek is a sharing network, and many users won't send files to someone who shares nothing. Tick the folders to share; the config below follows. Other users can only download from them, never change them. slskd scans them at every start, so a large library takes a few minutes the first time.

    Your Soulseek account. There is no sign-up form. The first time any program logs in with a username the server has never seen, that username is created with the password sent — so you simply choose both here.
    • Write them down. There is no email behind the account, no password reset and no recovery.
    • Taken names just fail. A name someone else owns comes back as "invalid credentials"; pick another. There is no way to check first, and a typo creates a new account instead of failing.
    • Use a throwaway password. The Soulseek protocol sends it to the server essentially in the clear. Never reuse a real one.
    • The username is public — everyone you exchange files with sees it.
    • One program per account. Signing in from a second client kicks the first one off. If you already use SoulseekQt or Nicotine+, either give slskd that login and stop the other, or make slskd its own account — running both on one account makes slskd drop in and out, which looks like a broken plugin.

    HTTPS off. The last two lines switch off slskd's built-in HTTPS, which has a bug on Windows. The plugin talks to slskd over plain http on this computer, so nothing is lost.

    Start it again
    
        
    Run slskd.exe again and keep the console window open while you use Soulseek — minimising is fine.
    
        
    Or make it start hidden at every login: paste this into a PowerShell window, after changing the path on the first line to where you put slskd.exe.
    
        
    $exe = "C:\slskd\slskd.exe"   # <- your path
$lnk = "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\slskd.lnk"
$s = (New-Object -ComObject WScript.Shell).CreateShortcut($lnk)
$s.TargetPath = "powershell.exe"
$s.Arguments = "-WindowStyle Hidden -Command Start-Process -WindowStyle Hidden '$exe'"
$s.Save()
    
        
    To undo: delete slskd.lnk from that Startup folder.

  1. 
        
    Download
    
        
    Get slskd-<version>-osx-arm64.zip (Apple silicon) or osx-x64.zip (Intel) from the releases page. Unzipping it (Safari does this by itself) leaves a folder named after the file in Downloads. Move that whole folder to your home folder and call it slskd — Terminal does both in one line:
    
        
    mv ~/Downloads/slskd-*-osx-*/ ~/slskd
    
        
    Keep the folder's contents together. slskd writes its settings file from the config folder that sits beside it; move the slskd file out on its own and no settings file ever appears.
    
        Open slskd releases

  2. 
        
    Run it once
    
        
    The first start has to come from Terminal (Spotlight → Terminal): macOS won't open an unsigned download from the Finder. Paste the three lines. The first clears the flag macOS puts on downloads (harmless if there is none), the second makes sure the program is executable, the third starts it.
    
        
    xattr -dr com.apple.quarantine ~/slskd
chmod +x ~/slskd/slskd
~/slskd/slskd
    
        
    Log lines scroll by. When one says Application started, slskd is running and has written its settings file. The line just above, Using application directory …, says where: on current builds that is ~/Library/Application Support/slskd (older ones used ~/.local/share/slskd; the rest of this page assumes the current one — swap the path if your log says otherwise). macOS may ask whether to allow incoming connections — allow it, or other Soulseek users can't reach you and downloads are slow to start. Then press Ctrl+C to stop it.
    
        
    Check before going on:
    
        
    ls "$HOME/Library/Application Support/slskd"
    
        
    You should see slskd.yml next to downloads and incomplete (the quotes matter — the path has a space in it). If the folder isn't there, slskd never got as far as starting — run ~/slskd/slskd again and read the first line marked ERR. The two usual causes: the slskd file was moved out of its folder (it needs config beside it), or something else already holds port 5030.

    Start it again
    
        
    ~/slskd/slskd in Terminal starts it; leave that window open.
    
        
    Or start it in the background at every login with a launch agent — paste the whole block into Terminal once.
    
        
    cat > ~/Library/LaunchAgents/com.slskd.plist <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.slskd</string>
  <key>ProgramArguments</key><array><string>${HOME}/slskd/slskd</string></array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>${HOME}/Library/Application Support/slskd/launchd.log</string>
  <key>StandardErrorPath</key><string>${HOME}/Library/Application Support/slskd/launchd.log</string>
</dict></plist>
EOF
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.slskd.plist
    
        
    To undo: launchctl bootout gui/$(id -u)/com.slskd and delete the plist.

  1. 
        
    Start the container
    
        
    One command, on the machine that will run it. slskd's settings and downloads are kept in ~/slskd on the host. ~/Music is the folder you share with other Soulseek users — change it to where your music lives. The container sees it as /music, read-only, and that is the path the config below shares.
    
        
    mkdir -p ~/slskd
docker run -d --name slskd --restart unless-stopped \
  -p 5030:5030 -p 50300:50300 \
  -v ~/slskd:/app \
  -v ~/Music:/music:ro \
  --user $(id -u):$(id -g) \
  slskd/slskd:latest

Finishing the connection in Viboplr

    
Open Soulseek in the Viboplr sidebar. The Connection section has three fields and a test button; here is what goes in each.


    

      

        slskd address
        
          
Where the plugin reaches slskd's web API. It is the address of slskd's own web page, without a path.

          
    
            
  • Same computer (the Windows and macOS guides above, or Docker on this machine): http://localhost:5030. The Connect button fills this in for you.
    • 
            
  • Another machine — Docker on a NAS, a home server, a Raspberry Pi: that machine's name or IP and the port, for example http://nas.local:5030 or http://192.168.1.20:5030. It must be reachable from the computer running Viboplr — if you can open the address in a browser there and see slskd's login page, the plugin can reach it too.
    • 
            
  • HTTPS: slskd also serves https://…:5031 with a self-signed certificate (not on Windows, where the config above switches it off). If you point the plugin at that, turn on Allow self-signed certificate; plain http on a home network is fine and simpler.
    • 
          

        		
      

      

        API key
        
          
The key you added to slskd.yml under web.authentication.api_keys. If you followed this page it is already in the plugin's field — it is the key shown at the top, and the two must match exactly. Changed it in the yml? Paste the new value here and press Test connection; slskd reads its config file live.

        		
      

      

        slskd runs on this computer
        
          
Found under Downloads in the plugin's settings. The plugin guesses from the address (localhost means yes); flip it if the guess is wrong. It decides what happens to a finished download:

          
    
            
  • On: Viboplr can play the file straight from slskd's downloads folder and Add to library copies it into a collection. If that folder sits inside one of your collections, finished files are picked up automatically.
    • 
            
  • Off (slskd on another machine): the files land in slskd's downloads folder over there. Share that folder on your network (SMB, NFS) and add the share as a music source in Viboplr's Collections; search and downloading work the same either way.
    • 
          

        		
      

    


    
Docker on another machine

    
The Docker tab's command works unchanged on a NAS or server; run it there. Two things differ from the same-computer case:

    
    
      
  • Reachability. Port 5030 must be open from your computer to that machine — the -p 5030:5030 in the command publishes it on the host; a firewall on the host may still need to allow it. Port 50300 is the Soulseek listen port and wants forwarding on your router, not on the host, so other users can reach you.
    • 
      
  • Where the music ends up. Downloads land in ~/slskd/downloads on that machine (the folder mounted as /app). Export it as a network share, mount it on your computer, and add the mount as a collection. Then turn slskd runs on this computer off in the plugin.
    • 
    

    
NAS app stores (Unraid, TrueNAS, Synology) often carry slskd as a one-click install; the address and key fields work the same — read the address off the NAS's app page and put the key in its config.


    
What the status line means

    
    
      
  • Not set up — the address or the key is empty.
    • 
      
  • slskd isn't reachable — nothing answered at the address. slskd isn't running, the address is wrong, or the port isn't open from here.
    • 
      
  • slskd rejected the API key — slskd answered but the key doesn't match its slskd.yml. Check for a copy-paste tail or a wrong indentation under api_keys.
    • 
      
  • slskd isn't signed in to Soulseek — the key works but slskd can't log in: check the Soulseek username and password in slskd.yml. The account is created the first time a username and password are used, so a typo here creates a new account instead of failing.
    • 
      
  • Ready — search away.
